# Open-disk DG-IIM diagnostic

This is a separate diagnostic application adapted from IBAMR 0.19.0's `flow_past_sphere.cpp` (BSD-3-Clause). It replaces the volume-generated closed sphere surface by an explicitly triangulated, zero-thickness circular disk in 3-D. Disk radius, radial rings, and azimuthal segments are read from the case input. The disk has a free perimeter; it is not capped or extruded.

The runs are feasibility/discriminator probes for finite-open-sheet support, not validated drag calculations. The initial K=450/K=0 inputs omit `use_direct_forcing`, so the surface is free to move with the flow. The fixed-coordinate inputs set `use_direct_forcing=TRUE`: this keeps the disk coordinates fixed but does not enforce no-slip. Current output reports target-coordinate lag, interface-velocity mismatch, spring and velocity-feedback callback terms, the combined registered IIM force callback, and `TAU_OUT` exterior-side traction. Older run logs have the superseded “spring reaction” label. For this open sheet, `TAU_OUT` alone is not established as the two-sided total force. The large mismatch and absent independent force/momentum closure mean these results cannot pass Stage A or validate the hawkmoth model. See `docs/iim_force_accounting_audit.md` for the source-level accounting.

## Exploratory target-velocity feedback probe (2026-10-03)

`results/open_disk_eta_probe_local_20261003_v1/` preserves an `ETA_S=0,1,10,100,1000` coefficient series against the fixed-coordinate crossflow setup. `ETA_S` is a numerical code-unit coefficient, not a calibrated physical damping parameter. The 1/10 cases barely changed surface slip; 100 reduced RMS mismatch about 10% but left it near the imposed 1-unit flow. At 1000, fixed-step runs triggered the deliberate timestep-change abort; permitting adaptive steps completed the short endpoint but produced a grossly unacceptable final RMS/max velocity mismatch of 41.39/193.83 code-speed units. This feedback callback is not a no-slip method. Historical stdout in this series mislabels the callback integral as “spring reaction” and uses unsupported physical-unit labels. The current source corrects those labels and separates spring and velocity-feedback terms; the refreshed runs are in `results/open_disk_force_audit_local_20261003_v1/`. Do not interpret either series as drag. Stage A remains **FAILED / UNVALIDATED**. See each study's machine summary and artifact hashes.

Build using the isolated libMesh-enabled IBAMR 0.19.0 prefix, not the original libMesh-disabled installation. Run from a fresh result directory so generated logs/visualization remain isolated. The input is a diagnostic input and intentionally does not claim grid convergence or an infinite-domain Stokes-drag match.
